# 《八戒不会飞》P1 核心玩法灰盒实施记录

> 变更记录：本阶段最初按长按需求实现；2026-09-19 已完成“点击产生一次向上冲量”的代码改造与自动测试。

## 1. 阶段结论

P1 已完成核心玩法灰盒。玩家可以从准备态开始游戏，通过连续点击控制八戒穿越持续生成的上下障碍，获得分数，并在碰撞后查看本局与历史最高分、重新开始。

本阶段验证的是完整玩法闭环与程序结构。山峰、石柱、火球、乌云、雷电、风火轮的正式规则属于 P2/P3，正式美术接入属于 P4。

## 3. 新增模块

```text
assets/scripts/
├─ config/
│  └─ P1GameplayConfig.ts
├─ gameplay/
│  ├─ BajieGrayboxView.ts
│  ├─ GrayboxObstaclePair.ts
│  ├─ ObjectPool.ts
│  └─ RunSession.ts
├─ platform/
│  └─ BestScoreStorage.ts
└─ p1/
   └─ P1Bootstrap.ts
```

- `P1GameplayConfig`：集中维护障碍尺寸、通道范围、生成间距、滚动速度和受击时长。
- `BajieGrayboxView`：可复用的八戒灰盒绘制组件，P0 入口继续兼容。
- `GrayboxObstaclePair`：维护一组上下障碍的显示、移动、碰撞区域与生命周期。
- `ObjectPool`：复用障碍对象，避免无尽玩法中持续创建和销毁节点。
- `RunSession`：保存本局分数，以障碍唯一编号保证每组障碍只计分一次。
- `BestScoreStorage`：通过 Cocos `sys.localStorage` 持久化最高分。
- `P1Bootstrap`：装配场景、输入、状态、生成、碰撞、HUD、暂停、结算与重开流程。

## 4. 已实现玩法

- `Ready → Playing → Hit → Result → Ready` 完整状态闭环。
- 每次有效点击将八戒纵向速度设置为固定扑动速度；点击之间持续受重力影响，停止点击后自然下落。
- 上下成对灰盒障碍按受约束的随机通道高度生成并向左滚动。
- 障碍离屏后进入对象池，后续生成时复用。
- 八戒越过障碍右边缘时加一分，同一障碍不重复得分。
- 圆形角色碰撞体与矩形障碍、上下边界发生碰撞后进入结算。
- HUD 显示当前分数、最高分、操作提示、暂停入口与调试数据。
- 右上角暂停；应用切到后台自动清除触摸并暂停，回到前台不擅自恢复。
- 最高分保存在本机；无效或异常存储值按零分处理。
- 结算后点击画面复位角色、分数、障碍队列和对象池状态。

## 7. Cocos Creator 验收步骤

1. 使用 Cocos Creator 3.8.8 打开项目根目录。
2. 打开 `assets/scenes/p1_game.scene` 并启动预览。
3. 连续点击画面观察八戒逐次扑耳上升，停止点击观察自然下落；按住不应持续施力。
4. 穿过障碍确认只增加一分；撞击障碍确认进入结算。
5. 点击结算界面重开，并确认分数归零、最高分保留。
6. 游戏中点击右上角暂停，再点击恢复。
7. P7 阶段生成 `build/p1-wechat`，再导入微信开发者工具做平台与真机验收。
