# 《八戒不会飞》第一版制作计划与验收

## 1. 制作原则

- 先验证手感，再批量制作美术。
- 先做静态障碍，再做动态障碍。
- 每个阶段都交付可运行版本。
- 任何新增需求先判断是否属于第一版。
- 不以“功能写完”作为完成标准，以真机验收通过为准。

## 2. 开发阶段

工期需要结合人员数量和素材生产方式另行估算。以下以产出物划分，不绑定具体日期。

### P0：工程与灰盒

目标：建立可构建的 Cocos 工程并验证飞行控制。P0 当时实现了长按方案；2026-09-19 需求已改为点击扑动，代码改造在确认后执行。

产出：

- Cocos Creator 工程。
- 单一 P0 启动场景；独立 Boot 场景延后到确有预载需求的 P5。
- 游戏状态机。
- 飞行控制与参数配置。
- 竖屏适配、安全区读取和微信生命周期处理。
- Web Desktop 与微信小游戏调试构建。

验收：

- TypeScript 严格校验和 Web 运行验证通过。
- 触摸取消、切后台不会补发冲量或造成幽灵输入。
- 不同帧率下飞行高度变化没有明显失控。
- 微信小游戏构建产物包含正确启动场景。

### P1：核心玩法灰盒

目标：使用占位素材完成可计分、可失败、可重开的完整循环。

产出：

- 一组上下占位障碍。
- 场景滚动、基础碰撞与计分。
- 最小对象池接口。
- 标题、HUD、暂停和结算占位界面。
- 本地最高分。

验收：

- 占位障碍可以持续生成。
- 不重复计分。
- 连续重开 20 次状态正常。

### P2：障碍系统

目标：完成首版静态障碍组合、数据驱动生成和受约束随机。

产出：

- 地面山峰、石柱与天空乌云的灰盒障碍。
- 上下障碍组合配置。
- 障碍尺寸、通道高度、间距与难度档位。
- 随机种子记录和安全回退。
- 批量公平性验证工具。

验收：

- 静态组合可以无限生成并正确回收。
- 10,000 组自动生成检查通过。
- 相邻通道变化与最小安全间隙符合配置。
- 记录种子后可以重现障碍序列。

### P3：动态障碍

目标：加入火球、雷电、风火轮，并完成受约束随机。

产出：

- 3 种动态障碍行为。
- 9 种组合。
- 动态障碍预警、冷却和运动边界。
- 双动态组合的解锁规则。

验收：

- 雷电有明确预警。
- 双动态组合遵守解锁和冷却规则。
- 暂停时动态障碍完全停止。

### P4：正式素材接入

目标：用正式资源替换占位内容，形成统一风格。

产出：

- 八戒完整首版动画。
- 天宫多层背景。
- 6 种正式障碍资源。
- 木牌与纸签 UI。
- 必要粒子特效。

验收：

- 角色和危险物体在真机小屏上清晰。
- 背景不会干扰碰撞判断。
- 动画 Pivot 无跳动。
- 视觉范围与碰撞范围符合玩家直觉。

### P5：游戏流程

目标：补齐首版启动、教学、暂停、结算、重开和本地记录流程。

产出：

- 启动与资源预载流程；仅在确有需要时增加 Boot 场景。
- 首次操作教学。
- 暂停、继续、失败结算与重开。
- 本地最高分和设置存储。
- 微信前后台生命周期完整处理。

验收：

- 首次进入和再次进入的引导状态正确。
- 连续重开 20 次无状态残留。
- 前后台切换不会自动恢复或产生幽灵输入。
- HUD、结算与本地最高分数据一致。

### P6：音效与手感

目标：补齐操作反馈并调整手感。

产出：

- 背景音乐。
- 必要音效。
- 撞击停顿、轻微震动、得分反馈。
- 参数调试记录。

验收：

- 高频耳朵音效不叠加爆音。
- 关闭声音后设置可保存。
- 失败反馈清晰且不过度拖慢重开。

### P7：微信真机验收

目标：形成第一版 Release Candidate。

产出：

- 性能和内存优化。
- 微信生命周期处理。
- 包体整理。
- 完整回归测试。
- 发布配置与版本号。

验收：

- 核心测试矩阵全部通过。
- 无阻断级问题。
- 目标设备性能满足内部基线。

## 3. 功能测试清单

### 3.1 输入

- [ ] 每次有效点击只产生一次向上冲量。
- [ ] 连续点击可以稳定维持或提升高度。
- [ ] 停止点击后立即只受重力影响并自然下落。
- [ ] 快速连续点击不会漏触发，也不会因触摸/鼠标双监听而重复触发。
- [ ] 多指触摸不导致状态错乱。
- [ ] UI 按钮点击不透传到角色。
- [ ] `Touch Cancel` 不补发冲量，后续新点击仍正常。
- [ ] 切后台后清除待处理输入，回到前台不自动扑动。

### 3.2 飞行与边界

- [ ] 上升速度不超过上限。
- [ ] 下降速度不超过上限。
- [ ] 角色旋转平滑。
- [ ] 撞到顶部按既定规则失败。
- [ ] 跌出底部只触发一次失败。
- [ ] 暂停时角色位置完全不变。

### 3.3 障碍物

- [ ] 9 种组合均可按档位出现。
- [ ] 前 3 分只出现教学允许组合。
- [ ] 动态障碍运动不超出配置范围。
- [ ] 雷电预警和碰撞激活同步。
- [ ] 离屏障碍正确回收。
- [ ] 回收后重新使用不会保留旧状态。
- [ ] 暂停时所有动画计时停止。

### 3.4 计分与存档

- [ ] 每组障碍只加 1 分。
- [ ] 撞击后不再加分。
- [ ] 重新开始时本局分数清零。
- [ ] 最高分正确更新。
- [ ] 重启小游戏后最高分保留。
- [ ] 存档损坏时使用默认值并可继续游戏。

### 3.5 UI

- [ ] 首次进入显示引导。
- [ ] 后续进入不重复强制引导。
- [ ] 暂停、继续、重开和返回标题流程正常。
- [ ] 结算分数与 HUD 最终分数一致。
- [ ] 新纪录标识只在确实刷新纪录时出现。
- [ ] 刘海屏、挖孔屏和圆角屏内容不被遮挡。

### 3.6 生命周期

- [ ] Playing 状态进入后台后自动暂停。
- [ ] 回到前台不自动恢复飞行。
- [ ] 暂停时进入后台不会叠加多个暂停界面。
- [ ] 锁屏/解锁后音频状态正常。
- [ ] 长时间后台后回到游戏不崩溃。

## 4. 公平性测试

- [ ] 批量生成 10,000 组无低于最低安全值的组合。
- [ ] 动态障碍最坏位置仍保留规定通道。
- [ ] 相邻通道中心变化符合限制。
- [ ] 双动态不会在禁止档位出现。
- [ ] 雷电不会连续出现。
- [ ] 生成重试失败时能回退到安全组合。
- [ ] 记录种子后可以重现相同障碍序列。

## 5. 视觉验收

- [ ] 八戒缩小到游戏尺寸后仍能看清脸和耳朵动作。
- [ ] 普通白云和障碍乌云不会混淆。
- [ ] 火球、雷电、风火轮在亮天空上仍清晰。
- [ ] 视觉特效不会遮挡通道。
- [ ] 碰撞体比耳朵尖、火焰拖尾等视觉边缘更宽容。
- [ ] 所有素材光照方向和纹理风格统一。
- [ ] 不含未经授权的字体、音乐和现有影视形象素材。

## 6. 性能测试

测试时至少覆盖一台较低性能、一台主流和一台高性能设备。

- [ ] 主流目标机稳定接近 60 FPS。
- [ ] 低性能目标机正常游戏不长期低于 45 FPS。
- [ ] 连续游玩 10 分钟无持续内存上涨。
- [ ] 动态障碍和粒子同时出现时无明显卡顿。
- [ ] 重新开始不会不断增加节点数量。
- [ ] 首次进入和重新开始无明显同步加载停顿。
- [ ] 音频并发数量处于限制内。

## 7. 问题优先级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 阻断 | 无法测试或无法发布 | 启动崩溃、无法进入游戏、存档导致黑屏 |
| P1 严重 | 核心玩法错误 | 无解障碍、重复计分、触摸卡住、碰撞失效 |
| P2 一般 | 明显影响体验 | 动画跳动、音效叠加、UI 被刘海遮挡 |
| P3 轻微 | 不影响核心使用 | 个别纹理接缝、次要文案或微小对齐问题 |

发布候选不得存在 P0、P1；P2 必须逐项评估并记录。

## 8. 第一版完成定义（Definition of Done）

第一版只有同时满足以下条件才算完成：

1. 需求范围中的所有必须项已实现。
2. 9 种障碍组合和动态行为已通过公平性验证。
3. 编辑器和微信真机均完成核心回归。
4. 美术、字体、音乐和音效的授权来源可追溯。
5. 无 P0、P1 问题。
6. 性能达到内部基线。
7. 文档与最终实现一致。
8. 由产品负责人实际试玩并确认飞行手感。
