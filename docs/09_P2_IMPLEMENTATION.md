# 《八戒不会飞》P2 障碍系统实施记录

## 1. 阶段结论

P2 已完成。当前版本在 P1 核心闭环上加入了数据驱动的静态障碍生成系统，能够无限生成并回收以下组合：

- 乌云 + 山峰。
- 乌云 + 石柱。

火球、雷电、风火轮及其动态行为明确留在 P3，不在本阶段提前混入。

## 2. 入口

- 当前运行场景：`assets/scenes/p1_game.scene`。
- 运行装配入口：`assets/scripts/p1/P1Bootstrap.ts`。
- P2 公平性工具：`tools/p2_fairness_check.ts`。

P2 继续复用已经验收的 P1 场景和运行装配组件，避免复制完整游戏循环形成两套逻辑。场景内标题已显示“P2 障碍系统灰盒”。后续 P5 整理正式流程时统一改为不带阶段号的正式 `game.scene`。

## 3. 新增结构

```text
assets/scripts/
├─ config/
│  └─ P2ObstacleConfig.ts
└─ obstacles/
   ├─ ObstacleTypes.ts
   ├─ SeededRandom.ts
   └─ StaticObstacleGenerator.ts

tools/
└─ p2_fairness_check.ts
```

- `ObstacleTypes`：定义山峰、石柱、乌云、静态组合和生成结果数据结构。
- `SeededRandom`：可复现的线性同余伪随机数生成器。
- `P2ObstacleConfig`：集中维护组合权重、尺寸、缩放、通道、间距、速度和难度档位。
- `StaticObstacleGenerator`：选择组合、采样通道中心、执行约束检查并生成可直接渲染的数据。
- `GrayboxObstaclePair`：根据数据绘制不同的山峰、石柱和乌云轮廓，同时复用统一碰撞与回收接口。

## 4. 难度档位

| 档位 | 分数 | 世界速度 | 通道高度 | 障碍间距 | 中心最大变化 |
|---|---:|---:|---:|---:|---:|
| Tutorial | 0～2 | 200 | 400 | 500 | 150 |
| Easy | 3～9 | 220 | 380 | 480 | 170 |
| Normal | 10～24 | 240 | 360 | 460 | 190 |
| Hard | 25～49 | 265 | 335 | 440 | 205 |
| Endless | 50+ | 285 | 315 | 430 | 210 |

绝对最小通道为 300，通道中心范围为 -210～210。静态障碍视觉缩放限制在 0.9～1.1，并在确定碰撞宽度前完成采样。

## 5. 生成流程

1. 根据当前分数选择难度档位。
2. 按权重选择“乌云 + 山峰”或“乌云 + 石柱”。
3. 以上一组通道中心为基准，计算当前档位允许的中心区间。
4. 在全局边界与相邻变化约束的交集中采样。
5. 验证最小通道、中心范围和相邻步长。
6. 最多重试 8 次；失败时回退到上一个合法中心。
7. 生成尺寸、缩放、组合、档位和唯一障碍编号。
8. 从对象池取得显示对象，离屏后重置并复用。

每局开始记录十六进制随机种子，调试 HUD 会显示 `seed` 与当前 `tier`。使用相同种子和相同分数序列，可复现完全一致的障碍序列。

| 检查项 | 结果 |
|---|---|
| 生成数量 | 10,000，全部通过 |
| 山峰组合 | 5,531 组 |
| 石柱组合 | 4,469 组 |
| 最小通道 | 无低于 300 的结果 |
| 通道中心边界 | 全部位于 -210～210 |
| 相邻中心变化 | 全部符合对应档位上限 |
| 外观缩放 | 全部位于 0.9～1.1 |
| 种子复现 | 两个同种子生成器逐组完全一致 |
| 安全回退 | 0 次；回退路径仍保留并有确定性结果 |

## 7. 其他验收

- TypeScript 严格类型检查通过。
- 山峰、石柱采用不同轮廓和配色，乌云与普通背景云有明显深浅区分。
- 障碍继续使用 P1 对象池，类型、组合和档位字段在回收时重置。
- 计分、碰撞、暂停、结算、点击飞行和最高分流程保持原接口。
- Cocos Creator 3.8.8 浏览器预览通过：山峰与石柱组合均正常滚动、回收和计分，运行控制台无警告或错误。

## 8. P3 边界

P3 将在现有数据模型上加入火球、雷电和风火轮，扩展为 3 × 3 共 9 种组合，并加入正弦运动、旋转、雷电预警/激活/冷却、连续动态限制和最坏运动包围盒校验。P2 不包含这些运行时行为。
